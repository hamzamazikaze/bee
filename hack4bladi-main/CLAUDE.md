# Hackathon mode

We are in a hackathon. Time is the scarce resource.

- Fast results over perfect ones: ship the smallest working change, then move on.
- Short answers: code first, one or two lines of explanation, no essays or option surveys.
- Test only the essential: one quick check that the happy path works (run it, click it, curl it). No test suites, no edge-case coverage, no refactors "while we're here".
- Don't ask clarifying questions when a sensible default exists — pick it, state it, proceed.
- Skip: docs, ADRs, CI, perf work, abstractions for later. Revisit after the demo if the project survives.
